# 生成程序的优化档位

编译器自身的 Cargo Debug/Release profile 与生成程序的优化档位独立。两种编译器默认都生成 O2；`-O0` 可显式生成调试档，`-O3` 可选择更激进的优化。`-O1` 同样可用，其他值拒绝。

```powershell
mascript-compiler-llvm build main.ms -O2 -o build/main.exe
mascript-compiler-llvm run main.ms -O3
mascript-compiler-llvm build main.ms -O3 --emit-dir build/ir
```

同一档位传入 LLVM TargetMachine、LLVM 新 PassManager 的 `default<O0/1/2/3>` 管线，以及编译完整 Rust 运行时的 `rustc -C opt-level=N`。目标机器沿用宿主 CPU 特性。原生依赖的预编译文件保持原样；维护者 C 源码回退仍为 O2。不启用 fast-math，保留整数溢出、除零、数组边界检查和 GC 可达性保护。

`--emit-dir` 输出 `<源码名>.raw.ll`（优化前）、`.opt.ll`（完整优化后）和 `.s`（同档位汇编）。输出错误会停止编译；不同档位使用不同目录，避免覆盖证据。

fama 的项目 `settings.toml` 中 `[build] opt-level = 0/1/2/3` 现在对 build/run 生效，缺省为 2。嵌入式编译器和全局配置的外部编译器路径传入同一档位。旧版外部编译器不支持这些参数时会明确失败，需同步更新。

字符串字典索引继续拥有独立字节，字符串键单独使用 `HashMap<Vec<u8>, usize>`。contains/get/update/remove 借助标准库切片查找，不再为查询分配临时 Vec；只有新键插入复制一次。遍历顺序、删除压缩与 GC 追踪均保持原契约。普通字符串拼接继续保持不可变语义；下述局部追加循环使用私有缓冲区消除重复前缀复制。

O1/O2/O3 在 LLVM 模块优化前，对用户函数调用图作保守判定，消除无托管根、无分配、无未知原生调用函数的自动 GC enter/poll/leave。支持纯递归和互递归；未知调用、托管根或显式 GC 操作会阻止所在函数及其调用者被裁剪。O0 保留原有管理，入口帧始终保留。安全边界和 GC 回归见 `gc.md`。

`gc_charge(0)` 直接返回，避免对没有容量增长的字典更新等操作重复访问 TLS；非零增长的预算与回收阈值不变。本轮与上一轮 O2 的实测对照见 `../../bench/optimization-gc/report.md`。

## 局部字符串追加循环

O1/O2/O3 对 `while`、整数 `for` 中只用 `+=` 写入的局部字符串启用私有构建器。初值复制一次，循环内通过 `Vec<u8>` 几何扩容追加，公共出口一次性转成普通不可变字符串；总字节搬运从平方增长降为摊还线性。`break` 经公共出口物化，`continue` 保留缓冲区。此优化不依赖函数名、常量分片或基准参数，O0 保留普通拼接。

分析覆盖条件分支；条件/循环边界、右值或其他语句读取目标字符串、同名声明、普通重新赋值、全局变量、提前 return 都会阻止优化。嵌套循环各自分析，不把外层的中间状态延迟到外层出口。循环前保存的字符串别名继续引用原来的不可变字节。当前不优化需要在每轮观察增长结果的程序，也不引入 rope 或更改字符串 ABI。

构建器字节地址不暴露给语言或原生字符串调用，只用私有句柄注册 GC 根；容量增长计入预算，强制回收和嵌套调用也保持其存活。回归见 `tests/string_builder.rs`（O0/O2/O3 输出及 IR 路径）、`tests/gc_memory.rs`（十万次追加的实际分配次数和释放）。同机固定负载及批量对照见 `../../bench/optimization-string/report.md`。

## 字典索引热路径

字典键类型在编译期固定，数字索引以 `u64` 存储同类型键的完整位模式，省去每个哈希桶中的枚举标签。整数负值及极值不截断；浮点正负零、NaN payload 继续沿用原来的位模式区分。索引仍使用标准库随机 HashMap，不更换散列安全策略。

数字键写入使用 `entry` 合并查询与插入，已有条目更新后直接返回，不再结算容量增长；字符串查询继续借用字节，只有新增字符串键才复制。插入顺序、删除压缩、错误定位和原字符串键的 GC 可达性保持不变。GC 依据容器类型跳过完全不含字符串的字典扫描；包含字符串键或值时仍扫描有效条目。

上一轮数字索引优化的主要收益来自数字字典，当时 `dict_wordcount` 暂无明显改善；后续优化见下节。尚未合并语言层 contains/get/set。结果、九轮样本离散度和复现脚本见 `../../bench/optimization-map/report.md`；O3 不保证快于 O2，默认仍为 O2。

## 字符串字典连续查询与整数格式化

字符串字典保存一个最近命中的条目位置，连续 contains/get/set 对同一内容的查询可复用该位置；每次仍比较完整字节，不以地址或哈希相等代替键相等。未命中回退标准库随机哈希，未引入弱哈希。缓存仅保存索引，不持有查询字符串，也不增加其 GC 寿命；删除前清空缓存，避免墓碑压缩后引用错误条目。插入和更新维持原插入顺序及原键引用。

整数转字符串继续使用标准库 Display，先在 20 字节栈缓冲区格式化，再一次分配精确长度的托管字节。覆盖完整 i64 范围，包括负号与最小值，避免 String 转 Box 的额外缩容。字符串 ABI、不可变语义、分配预算和 GC 注册路径不变。实际单次分配断言见 `tests/gc_memory.rs`，词频各键计数和缓存失效测试见 `src/runtime/tests.rs`。

同机 O2/O3 对照、仅缓存阶段与最终结果见 `../../bench/optimization-wordcount/report.md`。该优化不依赖词频函数名、4096 个键或特定基准规模；未合并或重排语言层表达式求值。
