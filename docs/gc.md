# 自动内存管理

Mascript 默认对动态字符串、列表和字典执行非移动、暂停式标记清扫 GC。用户不需要也不能手动释放这些对象。对象地址在存活期间保持稳定。固定数组仍按值传递，其中的字符串引用参与追踪。

## 用户可见的生命周期

- 字符串共享不可变字节；字符串字面量使用静态存储，动态结果由 GC 管理。
- 列表和字典赋值、传参共享同一个容器，修改通过别名可见。
- 列表切片创建新容器，字符串元素继续共享原字符串。
- 局部变量、参数、全局变量、表达式临时值及集合内字符串都参与追踪。
- 临时表达式在语句结束后解除保护；普通块退出时清空局部根；函数返回移除整个根帧。
- GC 不承诺最后一次读取后立即释放。终结分支跳过的局部清理可能将最后一个值保留至对应槽覆盖或函数返回，不会因循环轮次不断增加根槽。
- 回收发生在语句边界和循环头。分配辅助函数内部不回收；原生函数不能在构造过程中主动调用回收诊断入口。
- 活跃集合自身持续增大时，内存仍会增长；GC 只能释放不可达对象。字典会在墓碑超过阈值时压缩历史槽位并保持现有元素的插入顺序。

## 编译器与运行时边界

`src/llvm_backend/gc.rs` 负责精确根槽、函数帧和安全点。固定大小栈槽放在函数入口，托管槽在注册前零初始化；所有返回路径都退出 GC 帧。语句求值过程中尚未写入槽位的新对象暂存在当前帧的构造保护列表，嵌套调用不会清除调用者的保护列表。

`src/runtime/gc.rs` 负责对象登记、标记、清扫和分配预算。字符串、列表缓冲区、字典数组及键索引的分配或扩容计入预算。初始预算为 256 KiB，每次收集后采用存活主要堆容量的两倍与 256 KiB 的较大值作为下一轮新增分配预算。该值不是进程内存硬上限，不包括全部分配器和哈希表元数据。

`src/runtime/{strings,containers,lists,maps}.rs` 保存可直接参与测试的运行时代码；`runtime_bootstrap.rs` 在构建时将这些源码与入口拼接。生产运行时仍由现有 rustc 链接流程构建，未新增第三方依赖。

正常退出释放所有托管对象。GC 注册表和系统分配器可能保留可复用容量，因此回收不等于进程 RSS 立即下降。

## 原生模块契约

现有字符串 ABI（指针、长度）不变，原生返回字符串使用 `mas_runtime_string_clone`。输入字符串只允许在同步调用期间借用；原生模块不能自行释放托管对象，也不能把托管指针保留到调用结束之后或发送到其他线程。需要长期保存时复制到原生模块自己的存储，返回语言侧时再克隆到托管堆。

当前 GC 面向现有单线程语言执行模型。未实现跨线程共享根、异步根、移动对象、分代或并发回收。后续新增嵌套容器等类型时必须同步扩展对象追踪规则，不能只增加语法支持。

`mas_gc_collect`、`mas_gc_live_objects`、`mas_gc_collections` 是内部原生诊断入口，用于回归，不是稳定的用户标准库 API。强制收集仍保护当前未完成语句，不能保证其临时对象立即消失。

## 验证

```powershell
cargo test --manifest-path mascript-compiler-llvm/Cargo.toml --offline
```

- `src/runtime/tests.rs`：直接编译真实运行时，验证清扫、集合子引用、共享切片、数组、嵌套构造保护和字典压缩。
- `tests/gc.rs`：生成并执行原生 EXE，验证百万轮分配、自动收集、返回值、递归、全局覆盖、复合赋值、隐式 keys 快照及 break/continue。
- `tests/gc_memory.rs`：System 计数分配器测量真实申请与释放差额，比较一万轮和十万轮工作量后的存活请求字节，不以 RSS 或仅删除注册项作为释放证据。

本次 GC 不代表完整运行时安全整改完成；未初始化全局访问和整数除零的语言诊断仍需独立修复。
