# 自动内存管理

Mas lang 默认对动态字符串、列表和字典执行非移动、暂停式标记清扫 GC。用户不需要也不能手动释放这些对象。对象地址在存活期间保持稳定。固定数组仍按值传递，其中的字符串引用参与追踪。

## 用户可见的生命周期

- 字符串共享不可变字节；字符串字面量使用静态存储，动态结果由 GC 管理。
- 列表和字典赋值、传参共享同一个容器，修改通过别名可见。
- 列表切片创建新容器，字符串元素继续共享原字符串。
- 局部变量、参数、全局变量、表达式临时值及集合内字符串都参与追踪。
- 临时表达式在语句结束后解除保护；普通块退出时清空局部根；函数返回移除整个根帧。
- GC 不承诺最后一次读取后立即释放。终结分支跳过的局部清理可能将最后一个值保留至对应槽覆盖或函数返回，不会因循环轮次不断增加根槽。
- 回收发生在语句边界和循环头。分配辅助函数内部不回收；原生函数不能在构造过程中主动调用回收诊断入口。
- 活跃集合自身持续增大时，内存仍会增长；GC 只能释放不可达对象。字典会在墓碑超过阈值时压缩历史槽位并保持现有元素的插入顺序。

## 编译器与运行时边界

`src/llvm_backend/gc.rs` 负责精确根槽、函数帧和安全点。固定大小栈槽放在函数入口，托管槽在注册前零初始化；所有返回路径都退出 GC 帧。语句求值过程中尚未写入槽位的新对象暂存在当前帧的构造保护列表，嵌套调用不会清除调用者的保护列表。

`src/llvm_backend/gc_elision.rs` 在 O1/O2/O3 的 LLVM 管线之前分析用户函数调用图。只有没有托管根、分配或未知调用的函数，才移除自动插入的 enter/poll/leave；纯递归环整体判定。有分配或原生调用的函数及其所有间接调用者保留管理。入口帧和用户显式 GC 调用始终保留，O0 不执行裁剪。裁剪后的函数不会分配、收集或清除调用者 pending，因此未完成表达式的保护不变；无分配计算期间可能延后自动收集，回收次数不属于稳定语言契约。

`src/runtime/gc.rs` 负责对象登记、标记、清扫和分配预算。字符串、列表缓冲区、字典数组及键索引的分配或扩容计入预算；新对象还计入 `(usize, GcObject)` 登记项大小，收集后的存活容量采用相同口径。字符串键索引独立拥有字节，使用标准库切片查询而不创建临时副本；字符串与其他标量分别使用索引，并同时计入容量预算。初始预算为 256 KiB，每次收集后采用存活主要堆容量的两倍与 256 KiB 的较大值作为下一轮新增分配预算。该值不是进程内存硬上限，不包括分配器元数据和登记表保留的空桶容量。

`src/runtime/{strings,string_builder,containers,lists,maps}.rs` 保存可直接参与测试的运行时代码；`runtime_bootstrap.rs` 在构建时将这些源码与入口拼接。生产运行时仍由现有 rustc 链接流程构建，未新增第三方依赖。

正常退出释放所有托管对象。GC 注册表和系统分配器可能保留可复用容量，因此回收不等于进程 RSS 立即下降。

## 原生模块契约

现有字符串 ABI（指针、长度）不变，原生返回字符串使用 `mas_runtime_string_clone`。输入字符串只允许在同步调用期间借用；原生模块不能自行释放托管对象，也不能把托管指针保留到调用结束之后或发送到其他线程。需要长期保存时复制到原生模块自己的存储，返回语言侧时再克隆到托管堆。

当前 GC 面向现有单线程语言执行模型。未实现跨线程共享根、异步根、移动对象、分代或并发回收。后续新增嵌套容器等类型时必须同步扩展对象追踪规则，不能只增加语法支持。

`mas_gc_collect`、`mas_gc_live_objects`、`mas_gc_collections` 是内部原生诊断入口，用于回归，不是稳定的用户标准库 API。强制收集仍保护当前未完成语句，不能保证其临时对象立即消失。

## 验证

```powershell
cargo test -p maslang --locked --offline
```

- `src/runtime/tests.rs`：直接编译真实运行时，验证清扫、集合子引用、共享切片、数组、嵌套构造保护和字典压缩。
- `tests/gc.rs`：在 O2/O3 下生成并执行原生 EXE，验证纯计算调用与间接分配混合时的临时保护，以及百万轮分配、自动收集、返回值、递归、全局覆盖、复合赋值、隐式 keys 快照及 break/continue。
- `tests/gc_memory.rs`：System 计数分配器测量真实申请与释放差额，比较一万轮和十万轮工作量后的存活请求字节，不以 RSS 或仅删除注册项作为释放证据。

全局变量按顶层语句顺序初始化。函数可以引用后续声明，但在声明完成前执行读取或赋值会报告带源码位置的“全局变量尚未初始化”错误并以状态 1 退出；初始化表达式中的间接自读同样拒绝。局部同名变量不受影响。

数值和数组边界检查见 `tests/numeric_safety.rs`：整数除零、溢出、数组越界与非法强制浮点转换均报告带源码位置的语言错误。此处的 GC 与已补边界检查不代表完整运行时错误模型已实现。

字符串构建器使用独占 `Box<Vec<u8>>` 作为内部 GC 对象，无子引用。编译器在函数入口零初始化并注册专用句柄根；循环出口转移字节所有权到不可变字符串并清空句柄根。构建器不会原地改动任何已发布字符串，缓冲区扩容不会使已有字符串或容器元素失效。GC 根、分配预算和整个对象清扫同样覆盖该对象。

数字字典索引按静态键类型保存 64 位位模式，容量预算使用对应的实际槽位大小。标记阶段跳过键和值均非字符串的字典；数字键配字符串值以及字符串键配任意值仍追踪有效条目。覆盖值后旧字符串可回收，更新不替换原字符串键。

字符串字典的单条查询缓存只持有 entries 索引；命中时比较仍由字典保活的原键字节，不保存临时查询指针，删除或压缩前失效。整数格式化的栈缓冲区仅在同步调用内存在，返回前复制到一次分配的 GC 托管字节区。

## 下标赋值

列表、固定数组和字典统一支持 `container[index] = value`，沿用现有语法（不支持下标复合赋值）。列表和数组要求整数下标，右值必须与元素类型一致。序列仅覆盖已有槽位，不扩展长度；负数和越界下标在写入前报错。数组长度固定，元素可变。

目标、下标、右值依次各求值一次，完成右值求值后检查边界。右值若改变列表长度，按更新后的长度检查。列表赋值及传参共享容器，数组赋值及传参复制值；数组下标赋值写回当前变量的原槽。`const` 限制绑定重新赋值，不冻结容器元素，与现有字典下标赋值语义一致。字符串元素替换后新引用参与 GC，旧引用没有其他持有者时可回收。

`tests/index_assignment.rs` 在 O0/O2/O3 下验证真实程序输出，并覆盖类型拒绝、越界写入、求值顺序、列表扩缩容和字符串回收。

## 冗余安全点与整数直接索引

O1/O2/O3 的 `gc_poll_elision.rs` 在既有无托管根函数裁剪前移除重复自动 poll：所有到达路径必须已经检查，且此后无分配或未知调用。只允许已知不分配的字典 get/contains/len 穿过检查区间；set、快照分配、未知调用、显式 GC 均保守保留后续检查。循环和分支合流参与不动点分析，不删除帧、根或显式诊断调用；O0 保持原安全点。根被清空但无新增分配时可能延后自动回收，不改变强制收集和可达性保护。

非负稠密整数键增加直接位置索引，原 entries 仍保存唯一键值及遍历顺序。直接索引只含整数位置，无新增托管子引用；缓冲区实际容量计入新增和存活预算，删除压缩后修正索引，容器析构时释放。字符串值的追踪继续扫描有效 entries，覆盖和删除不保留旧值。短字符串登记成本纳入预算后自动收集会更频繁，避免大量小载荷对象积压。


局部整数转换若被证明仅作字典查询/赋值键，O1+ 可借用函数内 20 字节缓冲；该缓冲不属于托管堆，不登记局部或临时堆根；字典本身及其他托管值继续按原规则保护。字典首次保存此键之前必须复制为 GC 字符串，更新只保留旧托管键，不能把栈地址放入 entries 或字符串索引。返回字符串、普通实参、容器值和其他可能逃逸的使用不执行此优化。半构造保护和字典写入后的自动安全点照常保留；纯整数溢出 intrinsic 与栈格式化不会分配，已纳入自动安全点的精确白名单。

## 结构体与可空值

结构体使用非移动的托管对象和共享引用语义。对象字段按 LLVM 目标布局排列；编译器生成静态指针偏移表，运行时只追踪这些位置，不把整数误认成地址。字符串、列表、字典、结构体、可空值以及字符串数组字段均纳入追踪，环通过迭代标记处理。对象使用八字节对齐的独占存储，清扫时释放整个载荷；当前语言字段的 ABI 对齐不超过八字节。

`Struct?` 直接使用对象指针，null 是空指针。其他 `T?` 的非空值使用单字段托管包装；`null` 不分配。包装的静态追踪表覆盖字符串、容器及字符串数组。`.value` 检查非空后读取，错误通过 `mas_numeric_error` 的代码 5 报告原始源码位置。

构造参数、字段赋值接收者和右值均只求值一次，临时根跨嵌套调用保持有效。数组字段的下标赋值保留原字段存储；取出数组后赋给普通变量仍是值复制。可空数组 `.value[index]` 写回包装中的数组；复制 `.value` 到新变量后独立修改。

`tests/records.rs` 覆盖 O0/O3 下递归树、循环引用、字段别名、可空标量/容器、数组字段写回、源码诊断和跨模块类型身份。结构体/可空类型的 extern ABI 已采用同步借用指针契约；返回值必须为当前线程的托管对象，非空类型不能返回 null。


`list<Struct>` 使用标签 5，槽位保存原生对象指针；GC 仅扫描列表当前长度内的引用，再沿结构体的偏移表追踪字段。切片复制引用，覆盖/移除释放旧槽的保活关系，循环图仍由标记清扫回收。元素表达式按顺序各执行一次，构造中的列表和元素通过临时根跨越后续实参调用。`tests/record_lists.rs` 在 O0/O3 下强制回收验证列表方法、对象别名、嵌套容器和环的释放。


## 复合容器与原生引用

可空基础元素使用独立运行时标签 6–9，槽位仍为托管载荷指针，列表查找按载荷内容比较；结构体及容器引用标签为 5，按身份匹配。字典新增 Reference 单元，用于结构体键及托管值，追踪键和值两个方向。基础键索引路径保持不变。数组的同构引用布局递归展开，字段追踪表与根槽使用相同规则。

C 对象使用 `native/include/mas_runtime.h` 中的 `mas_record_alloc` 及静态偏移表创建，或返回借入的现有对象。`mas_native_require_record` 在返回边界检查托管所有权及 null 约束；不验证 C 类型声明是否真实，C 仍需遵守字段布局、0/1 布尔及同步借用约定。保留现有 ABI 1 的基础类型及字符串接口，新增指针能力不更改 Time 预编译模块。

`tests/composite_containers.rs` 覆盖可空值查找、结构体字典键值、嵌套容器及数组写回；`tests/native_records.rs` 经真实 C 编译、链接和 O0/O3 执行覆盖 Time 字段布局、写回、托管返回、可空载荷、强制回收及错误所有权。语言语法与公开头文件的示例见文档项目的 `modules/native-structs.mdx`。
