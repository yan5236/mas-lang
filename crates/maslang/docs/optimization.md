# 生成程序的优化档位

编译器自身的 Cargo Debug/Release profile 与生成程序的优化档位独立。两种编译器默认都生成 O2；`-O0` 可显式生成调试档，`-O3` 可选择更激进的优化。`-O1` 同样可用，其他值拒绝。

```powershell
maslang build main.ms -O2 -o build/main.exe
maslang run main.ms -O3
maslang build main.ms -O3 --emit-dir build/ir
```

同一档位传入 LLVM TargetMachine、LLVM 新 PassManager 的 `default<O0/1/2/3>` 管线，以及编译完整 Rust 运行时的 `rustc -C opt-level=N`。目标机器沿用宿主 CPU 特性。原生依赖的预编译文件保持原样；维护者 C 源码回退仍为 O2。不启用 fast-math，保留整数溢出、除零、数组边界检查和 GC 可达性保护。

`--emit-dir` 输出 `<源码名>.raw.ll`（优化前）、`.opt.ll`（完整优化后）和 `.s`（同档位汇编）。输出错误会停止编译；不同档位使用不同目录，避免覆盖证据。

fama 的项目 `settings.toml` 中 `[build] opt-level = 0/1/2/3` 现在对 build/run 生效，缺省为 2。嵌入式编译器和全局配置的外部编译器路径传入同一档位。旧版外部编译器不支持这些参数时会明确失败，需同步更新。

字符串字典索引继续拥有独立字节，字符串键单独使用 `HashMap<Vec<u8>, usize>`。contains/get/update/remove 借助标准库切片查找，不再为查询分配临时 Vec；只有新键插入复制一次。遍历顺序、删除压缩与 GC 追踪均保持原契约。普通字符串拼接继续保持不可变语义；下述局部追加循环使用私有缓冲区消除重复前缀复制。

O1/O2/O3 在 LLVM 模块优化前，对用户函数调用图作保守判定，消除无托管根、无分配、无未知原生调用函数的自动 GC enter/poll/leave。支持纯递归和互递归；未知调用、托管根或显式 GC 操作会阻止所在函数及其调用者被裁剪。O0 保留原有管理，入口帧始终保留。安全边界和 GC 回归见 `gc.md`。

`gc_charge(0)` 直接返回，避免对没有容量增长的字典更新等操作重复访问 TLS；非零增长的预算与回收阈值不变。本轮与上一轮 O2 的实测对照见 `../../bench/optimization-gc/report.md`。

## 局部字符串追加循环

O1/O2/O3 对 `while`、整数 `for` 中只用 `+=` 写入的局部字符串启用私有构建器。初值复制一次，循环内通过 `Vec<u8>` 几何扩容追加，公共出口一次性转成普通不可变字符串；总字节搬运从平方增长降为摊还线性。`break` 经公共出口物化，`continue` 保留缓冲区。此优化不依赖函数名、常量分片或基准参数，O0 保留普通拼接。

分析覆盖条件分支；条件/循环边界、右值或其他语句读取目标字符串、同名声明、普通重新赋值、全局变量、提前 return 都会阻止优化。嵌套循环各自分析，不把外层的中间状态延迟到外层出口。循环前保存的字符串别名继续引用原来的不可变字节。当前不优化需要在每轮观察增长结果的程序，也不引入 rope 或更改字符串 ABI。

构建器字节地址不暴露给语言或原生字符串调用，只用私有句柄注册 GC 根；容量增长计入预算，强制回收和嵌套调用也保持其存活。回归见 `tests/string_builder.rs`（O0/O2/O3 输出及 IR 路径）、`tests/gc_memory.rs`（十万次追加的实际分配次数和释放）。同机固定负载及批量对照见 `../../bench/optimization-string/report.md`。

## 字典索引热路径

字典键类型在编译期固定，数字索引以 `u64` 存储同类型键的完整位模式，省去每个哈希桶中的枚举标签。整数负值及极值不截断；浮点正负零、NaN payload 继续沿用原来的位模式区分。散列部分仍使用标准库随机 HashMap，不更换散列安全策略；非负整数的直接索引见下节。

已有条目更新后直接返回，不结算容量增长；字符串查询继续借用字节，只有新增字符串键才复制。插入顺序、删除压缩、错误定位和原字符串键的 GC 可达性保持不变。GC 依据容器类型跳过完全不含字符串的字典扫描；包含字符串键或值时仍扫描有效条目。

上一轮数字索引优化的主要收益来自数字字典，当时 `dict_wordcount` 暂无明显改善；后续优化见下节。尚未合并语言层 contains/get/set。结果、九轮样本离散度和复现脚本见 `../../bench/optimization-map/report.md`；O3 不保证快于 O2，默认仍为 O2。

## 字符串字典连续查询与整数格式化

字符串字典保存一个最近命中的条目位置，连续 contains/get/set 对同一内容的查询可复用该位置；每次仍比较完整字节，不以地址或哈希相等代替键相等。未命中回退标准库随机哈希，未引入弱哈希。缓存仅保存索引，不持有查询字符串，也不增加其 GC 寿命；删除前清空缓存，避免墓碑压缩后引用错误条目。插入和更新维持原插入顺序及原键引用。

整数转字符串继续使用标准库 Display，先在 20 字节栈缓冲区格式化，再一次分配精确长度的托管字节。覆盖完整 i64 范围，包括负号与最小值，避免 String 转 Box 的额外缩容。字符串 ABI、不可变语义、分配预算和 GC 注册路径不变。实际单次分配断言见 `tests/gc_memory.rs`，词频各键计数和缓存失效测试见 `src/runtime/tests.rs`。

同机 O2/O3 对照、仅缓存阶段与最终结果见 `../../bench/optimization-wordcount/report.md`。该优化不依赖词频函数名、4096 个键或特定基准规模；未合并或重排语言层表达式求值。

## 稠密整数索引与字典循环安全点（2026-09-20）

非负整数键在已有直接索引范围内，或键值小于 `max(64, 2 * (len + 1))` 时，使用按二次幂扩展的 `Vec<usize>` 保存条目位置。空槽不代表键存在；负数、大整数、稀疏整数与浮点/布尔键继续走原随机哈希索引。增长范围由现有条目数约束，不按任意大键分配。回退路径保留 `entry` 单次哈希查找/插入，避免稀疏键首次插入重复散列。早期进入哈希表的整数不会因直接索引扩展重复插入；查询和删除在空槽处仍查哈希表。遍历继续以原 entries 顺序为准，删除压缩同步修正两处索引并裁剪直接索引尾部空洞。新增容量参与 GC 预算，容器释放时整体释放。

O1/O2/O3 在既有纯标量函数优化之前，沿控制流保守分析自动安全点：仅当所有前驱路径都已检查且之后没有潜在分配或未知调用，才移除重复 `mas_gc_poll`。完整类型后缀校验的字典 get/contains/len 可继续视为无分配；字典 set、keys/values、用户函数、未知原生调用、间接调用一律阻止跨越。分支合流与循环回边求不动点；入口检查、帧、根、显式 GC 调用保留。O0 不执行此裁剪，整数溢出和缺失键检查不变。

短字符串的 GC 新增预算与收集后存活预算均计入 `(usize, GcObject)` 登记项大小，避免只按几字节文本计算、积压大量登记对象。仍以 256 KiB 和存活主要容量两倍的较大值为阈值，不把登记表保留的空桶容量当成存活载荷。回收时机不是稳定语义；对象可达性、半构造保护与不可变字符串 ABI 保持不变。

验证见 `tests/map_optimization.rs`（O0/O2/O3 的真实词频、别名、混合键、GC、错误定位）、`src/runtime/tests.rs`（有序模型差分）和 `tests/gc_memory.rs`（真实分配释放）。固定最新工作量的完整同机 A/B 证据、九轮样本和复现脚本见 `../../bench/optimization-dict-20260920/report.md`；不以历史会话数字计算本轮收益。

## 临时字典键与查询调用成本（第二轮，2026-09-20）

用户函数及全局变量槽采用 LLVM internal 链接属性；语言模块已合并进入同一编译单元，因此可传播模块内部的常量并内联函数。原生 extern 符号及 mascript_entry 保持外部 ABI；全局值仍在原声明位置初始化，不提前求值或取消初始化检查。

O1/O2/O3 对局部 `var key = string(int表达式)` 检查声明后的整个词法块。仅直接作为 contains 参数、字典读取下标或赋值键时，可在函数入口分配独立 20 字节栈缓冲，每轮按标准 Display 重新格式化。分析拒绝返回字符串、普通函数实参、列表/字典值、变量别名、重新赋值、同名遮蔽和嵌套循环；不能证明安全时完整回退，O0 始终使用普通托管字符串。不限定名称、整数范围、键数量或基准工作量。

字典写入借用键时，已有条目仅更新值并保留原键；新键复制为普通 GC 字符串后交给既有插入逻辑。查询借用缓冲不会留存其地址。因而函数返回后的字典、keys() 快照、删除重插、别名与强制 GC 均不依赖栈缓冲寿命。数值格式、插入顺序、表达式求值次数和错误行为不变。

运行时的查询、包含与写入辅助函数在固定键值类型的 ABI 包装层内展开，减少枚举分支和临时搬运。整数键/整数值读取另提供同语义的紧凑入口，将路径、源码和 span 组成只读 C 布局常量，热调用仅传递一个诊断指针；只有缺失键时才读取它，完整报错位置仍保留。旧运行时入口保留。

整数加减乘使用 LLVM sadd/ssub/smul.with.overflow.i64 同时产生结果与溢出标志；溢出分支仍调用原诊断，回绕值不流入正常结果。GC 分析只对白名单中的这三个确切 intrinsic 和不分配的栈格式化入口放行，未知原生函数及字典写入仍保守处理。

回归与测量见 `tests/map_optimization.rs`、`src/llvm_backend/borrowed_keys.rs` 的分析边界测试，以及 `../../bench/optimization-dict-round2/report.md`。第二轮基线冻结为上一轮最终编译器，正式对照使用相同原始 Benchmark 源码和参数；预建字符串键的改写版本只用于定位分配成本，不计入优化成绩。
