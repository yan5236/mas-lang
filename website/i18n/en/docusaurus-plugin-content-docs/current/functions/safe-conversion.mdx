# Safe Conversion

Safe conversion functions return a result object instead of producing a runtime error. Use `.ok` and `.value` to check success and access the converted value.

## try_int()

```mas-lang
var result = try_int("123")
if result.ok:
    print(result.value)   // 123
else:
    print("conversion failed")
```

## try_float()

```mas-lang
var result = try_float("3.14")
if result.ok:
    print(result.value)   // 3.14
```

## try_bool()

```mas-lang
var result = try_bool("true")
if result.ok:
    print(result.value)   // true
```

`try_bool(string)` accepts only the exact lowercase strings `"true"` and `"false"`; forms such as `"TRUE"` yield `ok=false`.

## Return Type

Safe conversion functions return an internal result value (shown as `try_result<T>` in diagnostics) with two read-only properties:

| Property | Type | Description |
|----------|------|-------------|
| `.ok` | bool | Whether the conversion succeeded |
| `.value` | T | The converted value (only valid when ok is true) |

On failure `.value` is a harmless placeholder: `0` for `try_int`, `0.0` for `try_float`, `false` for `try_bool`. Check `.ok` first and never rely on the failed content.

Native modules can build strings from arbitrary bytes. `try_int`, `try_float`, and `try_bool` return `ok=false` when the bytes are not valid UTF-8 and never terminate the process; strict conversions such as `int()` and `float()` still report "the string is not valid UTF-8 text" and exit with status code 1.

`try_string()` does not exist because string conversion almost never fails.

## Input Types and Rules

`try_int`, `try_float`, and `try_bool` all accept primitive types (`int`, `float`, `bool`, `string`) and reject containers, structs, and nullable values.

- `try_int` accepts integers, booleans, strings, and floats. Integer and boolean conversions always succeed; a string must be a pure decimal integer with no whitespace trimming: `try_int(" 12")` has `ok` `false`
- `try_float` string parsing accepts decimal and exponent notation, and `"inf"` and `"nan"` count as valid floats (`ok=true`)
- `try_int(float)` checks the range first and then truncates the fractional part toward zero. NaN, positive and negative infinity, and values below `-9223372036854775808.0` or at or above `9223372036854775808.0` return `ok=false` with `value` `0`

`int(float)` uses the same range check and, on failure, reports a runtime error with a source location and exits with status code 1; a failed `int(string)` parse carries no source location.

For example:

```mas-lang
var result = try_int(true)   // result.ok == true, result.value == 1
```

```mas-lang
var huge = try_int(float("1e20"))
func main():
    print(huge.ok)      // false
    var small = try_int(-3.9)
    print(small.value)  // -3
```

Float-to-integer conversion checks the value after it has already been rounded to a 64-bit float, so the usable range is `[-2^63, 2^63)`. For instance `-9223372036854776000.0` and `-9223372036854775809.0` both round to exactly `-2^63` first and therefore convert successfully, while the genuinely smaller neighbouring value `-9223372036854777856.0` fails. `9223372036854775807.0` rounds to `2^63` and therefore fails. When you need the exact decimal integer, use an integer literal or `try_int("...")` rather than going through `float`.
