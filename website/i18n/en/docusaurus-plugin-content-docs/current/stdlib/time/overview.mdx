# time — Standard Library

The `time` module provides wall-clock time retrieval, time formatting, and monotonic clock timing. The package version is `0.2.0` with native ABI version `2`.

## Installation

`time` ships with the repository as a package (`stdlib/time`); it is not a compiler built-in module. Declare the dependency in your project's `settings.toml` and install it:

```toml
[dependencies]
time = { path = "../../../stdlib/time", version = "0.2.0" }
```

Then run `fama install` (no need to reinstall once it is present in `mod_module/time@0.2.0/`). See `examples/projects/time-api` for a complete example.

## Import

```mas-lang
import time { unix_seconds, now_utc, monotonic_millis, sleep, try_sleep }
```

Import only what you need. The result structs `TimeStatus`, `TimeIntResult`, and `TimeStringResult` are exported from the same entry point.

## Function Overview

Strict functions keep their original names and return types. On failure they print a Chinese runtime error and exit with status code `1`:

| Function | Return Type | Description |
|----------|-------------|-------------|
| `unix_seconds()` | `int` | Current Unix timestamp (seconds) |
| `unix_millis()` | `int` | Current Unix timestamp (milliseconds) |
| `now_utc()` | `string` | ISO 8601 / RFC 3339 formatted UTC string |
| `now_email_date()` | `string` | RFC 2822 formatted UTC string |
| `now_http_date()` | `string` | HTTP-date formatted UTC string |
| `monotonic_millis()` | `int` | Monotonic clock millisecond counter |
| `sleep(ms)` | void | Sleep the thread for the given milliseconds |

Recoverable functions never terminate the process; failures are reported through the result struct:

| Function | Return Type | Description |
|----------|-------------|-------------|
| `try_unix_seconds()` | `TimeIntResult` | Safely read the Unix timestamp in seconds |
| `try_unix_millis()` | `TimeIntResult` | Safely read the Unix timestamp in milliseconds |
| `try_monotonic_millis()` | `TimeIntResult` | Safely read the monotonic millisecond counter |
| `try_now_utc()` | `TimeStringResult` | Safely read the ISO 8601 UTC string |
| `try_now_email_date()` | `TimeStringResult` | Safely read the RFC 2822 UTC string |
| `try_now_http_date()` | `TimeStringResult` | Safely read the HTTP-date UTC string |
| `try_sleep(ms)` | `TimeStatus` | Safe sleep; negative waits no longer abort the process |

## Result Structs

The three structs are re-exported from `index.ms`, and their field names follow the repository-wide `try_result` convention:

```mas-lang
import time { try_sleep }

func main():
    var status = try_sleep(-1)
    if not status.ok:
        print("wait failed, code " + string(status.code))
    print("still running")
```

| Struct | Fields |
|--------|--------|
| `TimeStatus` | `ok: bool`, `code: int` |
| `TimeIntResult` | `ok: bool`, `code: int`, `value: int` |
| `TimeStringResult` | `ok: bool`, `code: int`, `value: string` |

When `ok` is `false`, `value` holds a harmless placeholder (`0` or the empty string); always check `ok` before reading `value`.

## Error Codes

| Code | Meaning | Reported by |
|------|---------|-------------|
| `0` | Success | All |
| `1` | Host clock read failure | Timestamp and formatting readers |
| `2` | Host clock is earlier than the Unix epoch (Windows only) | Same as above |
| `3` | UTC decomposition failure | Formatting readers |
| `4` | Time formatting failure | Formatting readers |
| `5` | Negative wait argument | `try_sleep` |
| `6` | Blocking wait failure | `try_sleep` |
| `7` | Monotonic clock read failure | `try_monotonic_millis` |

On a non-zero code the strict functions call the internal `mas_time_fail(code)`, which prints the same Chinese `运行时错误: ...` message as version 0.1.0 and exits with status code `1`.

## Prebuilt Native ABI

`0.2.0` bumps the native ABI to `2`: the native layer no longer aborts on predictable host failures, it fills in result structs and reports status codes instead. Prebuilt objects for all five targets must be rebuilt from the new sources:

| Target triple | Status |
|---------------|--------|
| `x86_64-pc-windows-msvc` | Refreshed for `0.2.0` / ABI 2 (built locally with the MSVC toolchain) |
| `x86_64-unknown-linux-gnu` | Refreshed for `0.2.0` / ABI 2 (built by Actions `ubuntu-24.04`) |
| `aarch64-unknown-linux-gnu` | Refreshed for `0.2.0` / ABI 2 (built by Actions `ubuntu-24.04-arm`) |
| `x86_64-apple-darwin` | Refreshed for `0.2.0` / ABI 2 (built by Actions `macos-15-intel`) |
| `aarch64-apple-darwin` | Refreshed for `0.2.0` / ABI 2 (built by Actions `macos-15`) |

All five targets were rebuilt from the `0.2.0` sources. If the C sources, headers, or `native.abi` change again, rerun the `time-artifacts` workflow; otherwise the compiler rejects the stale artifacts with a Chinese diagnostic before linking instead of mixing old and new objects. See `stdlib/time/README.md` for details.

## Notes

- All wall-clock functions return **UTC time**; local timezone conversion is not provided
- `monotonic_millis` starts at system boot, not the Unix epoch — do not mix with wall-clock time. On Windows it uses the system tick counter with a resolution of about 15.6 ms, so measuring very short intervals can jump by 0 or 16 ms
- On Windows a host clock earlier than 1970-01-01 UTC yields `ok = false, code = 2`; negative timestamps are legal values and are **never** used as a failure sentinel
- `sleep(ms)` with a negative value still exits with status code `1`; use `try_sleep(ms)` when the failure branch must keep running
