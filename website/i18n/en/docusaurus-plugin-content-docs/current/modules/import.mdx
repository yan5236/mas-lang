# Import

## Prerequisites

`import` and `export import` usually require a project context: a `settings.toml` that can be found by walking up from the entry file. When running a single `.ms` file (for example `maslang run hello.ms` in a directory without `settings.toml`), only the bundled `io` standard library can be resolved; other imports still report that module imports must be expanded before semantic analysis. To import project modules or third-party packages, create a project with `fama new`, or provide the project configuration manually.

## Import Syntax

Use `import` to bring symbols from other modules into scope:

```mas-lang
// Named import
import utils.math { add, sub }

// Rename an imported function; a trailing comma is allowed
import time {
    sleep as time_sleep,
    unix_seconds,
}

// Give the module an alias; only the listed members are reached through t
import time as t {
    sleep,
    unix_millis as millis,
}

func main():
    time_sleep(10)
    t.sleep(10)
    print(t.millis())
```

Members of an aliased module import are reachable only through the alias (here `t.sleep` and `t.millis`); `sleep` is not introduced into the current file directly. A member alias (`unix_millis as millis`) is likewise written `t.millis` inside the aliased module.

```mas-lang
// Wildcard import
import utils.math.*

// Import an installed dependency package (declare it in settings.toml, then run fama install)
import time { unix_seconds }

// The bundled standard library needs no dependency declaration; import it directly
import io { stdout, write_text_to }
```

Named lists may be written on one line or across lines, and allow a trailing comma. Module aliases within one file of a project must be unique, and must not collide with top-level declarations or directly imported names.

Named imports, wildcard imports, and re-exports share the import namespace of the current file. If two different symbols claim the same name, the compiler reports an error; use a member alias or a module alias to tell them apart. Importing the same symbol again under the same name is allowed.

A named import's visible name also cannot be the same as a top-level declaration (`func`, `struct`, `var`, `const`) in this file, otherwise it reports a clash between the import name and a top-level declaration of the current module.

## Module Paths

- Paths are dot-separated: `utils.math` maps to `src/utils/math.ms`
- `index.ms` is the directory entry file; `utils` maps to `src/utils/index.ms`
- Paths **always resolve from the package root's `src/`**, regardless of the directory of the file containing the import. For example, to reference the sibling `math.ms` from `src/utils/index.ms`, you must write `utils.math`, not `math`

## The local Prefix

When a local module conflicts with an external package name, use `local.` to force local resolution:

```mas-lang
import local.time { format }
```

## Resolution Order

Resolution is decided by the `settings.toml` of the package that contains the import:

1. Names declared in that package's `[dependencies]` resolve to the installed package at its declared version.
2. A bare name that matches a bundled standard library (currently `io`), when that package does not declare a same-named dependency, resolves to the package shipped with the toolchain; it takes precedence over project source with the same name.
3. Other names resolve to local modules under `src/`.

The `local.` prefix skips the first two steps and always resolves project source. A dependency must first be declared with `fama add` and then installed with `fama install` into `mod_module/<name>@<version>/`; when it is missing, the compiler reports that the dependency is not installed and that `fama install` should be run first. The bundled standard library needs no install and is not recorded in `mod-lock.yml`; third-party packages may likewise omit their own `io` dependency declaration and still get the bundled `io`.

If one executable's module graph actually loads both the bundled `io` and an explicitly declared `io` native implementation, the compiler reports an error before linking and asks you to remove `[dependencies].io` in favor of the bundled package, or to declare the same dependency from every importer. Declaring it without importing it is not a conflict.
